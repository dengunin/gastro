# Учебное пособие по гастроэнтерологии

Закрытый проект в приватном репозитории [dengunin/gastro](https://github.com/dengunin/gastro). GitHub хранит исходники и проверяет сборку. Размещение сайта с входом по паролю пока отложено; автоматической публикации нет. Корень репозитория — **эта папка**, а не родительская рабочая папка с конспектами и личными файлами.

## Структура

```text
.github/workflows/build.yml   # сборка и проверка без публикации
topics/
  01_metody_diagnostiki/
    meta.json                # номер, название, дисциплина
    1_full.md ... 6_images.md # учебные исходники
    *.json                   # дополнительные данные вёрстки и источников
    images/                  # исходные WebP/SVG/PNG/JPEG схемы
  02_farmakologiya/
    ...
  ...
  43_ot_zhaloby_k_diagnozu/
tools/
  build_site.py              # генератор
  check_site.py              # проверка внутренних ссылок и путей
  tests/test_build_site.py   # проверка обнаружения тем и пересборки
  site_assets/               # CSS, JS, шрифты, фирменные SVG
requirements.txt
.gitignore
README.md
site/                        # результат сборки, не хранится в Git
```

## Локальная сборка и проверка

Нужен Python 3.12. Команды из корня этого проекта одинаковы для Windows, Linux и macOS:

```sh
python -m venv .venv
```

Активируйте окружение: `.venv\Scripts\Activate.ps1` в PowerShell либо `source .venv/bin/activate` в Linux/macOS. Далее:

```sh
python -m pip install -r requirements.txt
python -m unittest discover -s tools/tests
python tools/build_site.py
python tools/check_site.py
python -m http.server 8000 --directory site
```

Откройте [локальную главную](http://localhost:8000/). Для проверки адреса с подпапкой запустите сервер из корня проекта без `--directory site` и откройте [сайт под /site/](http://localhost:8000/site/).

Генератор определяет корень по расположению `build_site.py`, поэтому не зависит от текущего рабочего каталога. Пересборка очищает только свою папку `site/`, удаляя устаревшие страницы. `check_site.py` проверяет файлы, якоря, CSS-ресурсы, адреса схем и поиска, моделируя публикацию в `/repository-name/`.

## Как добавить тему — 5 шагов

1. Создайте `topics/44_new_topic/`. Номер в имени папки должен совпадать с `number` в метаданных. Используйте латинские буквы, цифры и подчёркивания.
2. Создайте UTF-8 файл `meta.json`:

   ```json
   {
     "number": 44,
     "title": "Название новой темы",
     "discipline": "Гастроэнтерология"
   }
   ```

3. Добавьте `1_full.md`, `2_short.md`, `3_card.md`, `4_tests.md`, `5_cases.md`, `6_images.md`. Это полная версия, краткий материал, карточка, тест с ответами, задачи и описания схем. Порядок разделов и медицинские формулировки берутся из Markdown. Папки без `meta.json` не публикуются.
4. Поместите готовые схемы в `images/`: например, `44-01-light.svg` и `44-01-dark.svg`. Поддерживаются `.webp`, `.svg`, `.png`, `.jpg`, `.jpeg`. Для включения в материал используйте блок, как в Теме 1:

   ```md
   > **[ИЗОБРАЖЕНИЕ 44-01] Название схемы**
   > Описание: Что показано на схеме.
   ```

   Дополнительные `structure.json`, `sources.json`, `verify.json`, `figures.json`, `cases.json` и `5_cases_staged.md` нужны для специальной вёрстки Темы 1. Темы 2–43 используют `layout.json` и компоненты `tools/reference_topic.py`: это перенос эталонного оформления с сохранением исходного Markdown. Для новой темы используйте [краткую инструкцию](AGENT_TOPIC_MIGRATION.md).
5. Выполните `python tools/build_site.py` и `python tools/check_site.py`, просмотрите страницы, затем сохраните исходники в Git. Главная, «Все темы», название дисциплины в шапке и поиск каталога обновятся автоматически. Редактировать список тем в генераторе не нужно.

Темы сортируются по дисциплине и номеру. В каталоге разных дисциплин есть отдельные группы; на странице темы показывается её дисциплина. Обязательные поля метаданных проверяются, повтор номера в одной дисциплине вызывает ошибку.

## Режимы страниц

Тема 1 сохраняет существующую специальную вёрстку из `structure.json`: маршруты изучения, шпаргалку, интерактивный тест, поэтапные задачи и реестр источников. Тема 2 приведена к этому образцу: три маршрута, семь крупных блоков в кратком и полном материале, плитки шпаргалки, тест из 100 вопросов с попытками по 20 и три задачи с этапами «Условие → Решение → Разбор». Библиография и пометки второй темы перенесены из исходников без присвоения статуса сверки.

Темы 3–43 приведены к образцу темы 2: маршруты изучения, семь тематических частей, плитки шпаргалки со ссылками, интерактивный тест, поэтапные задачи, схемы и карточки источников. Собственная группировка каждой темы хранится в `layout.json`. Исходные банки содержат по 20 или 100 вопросов; в теме 25 ключи есть только к первым 20, поэтому вопросы 21–100 сохранены отдельно без автоматической оценки. Генератор не приписывает материалам статус проверки. Медицинская проверка содержания не входит в техническую подготовку репозитория. Подробности — в [отчёте переноса](MIGRATION_03_43_REPORT.md).

При работе через HTTP(S) переходы между разделами одной темы выполняет `assets/navigation.js`: шапка, меню, его ссылки и нижняя панель сохраняются в DOM, заменяется только содержимое `main`. Оглавления заранее включены в меню; переключаются активные пункты и видимость списков. Работают прямые ссылки, якоря, «Назад/Вперёд» и восстановление тестовой попытки. При ошибке загрузки, переходе между темами или открытии через `file://` используются обычные HTML-ссылки. Для проверки отсутствия перезагрузок запускайте локальный HTTP-сервер, как описано выше.

`6_images.md` хранит описания и промпты как исходник. Страница «Схемы» показывает иллюстрации, упомянутые в учебном материале, с их подписями и описаниями. Если пары изображений нет, отображается сообщение о недостающей схеме.

## Закрытый доступ и размещение

Репозиторий приватный: доступ к исходникам есть у владельца и приглашённых им участников. Workflow `.github/workflows/build.yml` устанавливает зависимости, запускает тесты, собирает сайт и проверяет ссылки при push в `main`, pull request и ручном запуске. Заданий публикации и разрешений `pages: write` нет.

Для просмотра используйте локальную сборку и HTTP-сервер по инструкции выше. Папка `site/` создаётся из исходников и не хранится в Git. Все внутренние пути относительные; сборка поддерживает размещение в подпапке. Общие ресурсы находятся в `site/assets/`, страницы темы — в `site/topics/<slug>/`, схемы — в `site/topics/<slug>/img/`.

Приватный репозиторий сам по себе не закрывает опубликованный GitHub Pages-сайт. Для будущего доступа по паролю потребуется серверная авторизация на выбранном хостинге; она должна защищать HTML, изображения, поиск и прочие файлы. До выбора хостинга сайт не публикуется. См. [документацию GitHub об открытости Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site).

## Что исключено

`site/`, `_archive_*`, `_system/`, личные заметки, черновики, локальные окружения, временные файлы, настройки редакторов, рабочие аудиты и дизайн-макеты исключены через `.gitignore`. В эту папку перенесены только разрешённые учебные исходники и используемые ресурсы. Имена личных файлов бывают произвольными: храните новые личные материалы в игнорируемых `notes/`, `private/` или `drafts/`, а перед будущим коммитом проверяйте `git status`.

Версии Python-пакетов закреплены в `requirements.txt`. Проверка ссылок и тесты используют стандартную библиотеку Python. Для дополнительной проверки сохранности текста при переносе установите `requirements-qa.txt`, затем выполните `python tools/migrate_reference.py validate NN`. Она собирает только выбранную тему во временную рабочую папку и обновляет отчёт в `reports/reference-migration/`.

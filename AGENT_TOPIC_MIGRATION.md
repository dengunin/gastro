# Перенос одной темы по образцу темы 2

Работай только с назначенной темой `topics/NN_slug`. Образец — `topics/02_farmakologiya/layout.json`; общие компоненты — `tools/reference_topic.py`.

1. Выполни `python tools/migrate_reference.py inspect NN`. Достаточно заголовков; длинные исходники целиком не читай.
2. Создай `layout.json` с `reference: true` и семью элементами `parts`. У каждого — уникальный `id`, тематические `title` и `step`, список исходных номеров `sections`. Обычная группировка: 1–5; 6–7; 8–11; 12; 13–15; 16–18; 19–22. Адаптируй её по заголовкам для нестандартной темы. Покрой все разделы полного и краткого материалов, сохрани порядок. Ненумерованное введение включи через `include_unnumbered: true` у первой части.
3. Добавь `card_refs`: по одной строке с номером подходящего раздела полной версии на каждый блок шпаргалки, в исходном порядке, без «Одной строкой». Добавь короткие `descriptions.short` и `descriptions.full`, соответствующие этой теме.
4. Markdown, медицинские формулировки, числа, ключи тестов, случаи, схемы и пометки «проверить» не меняй. Не копируй содержание фармакологии и не присваивай источникам статус сверки.
5. Только в теме 25 добавь `quiz_unkeyed_policy: "preserve"`: у вопросов 21–100 нет ключей; они сохраняются отдельным блоком без автоматической оценки.
6. Выполни `python tools/migrate_reference.py validate NN`. Проверка собирает только твою тему в рабочую папку. Исправляй собственную конфигурацию; общие ошибки парсера с точным сообщением передай родителю. Общие файлы и другие темы не редактируй, полную сборку не запускай.
7. Заверши коротко: файл, результат проверки, ограничения. Других агентов не запускай.

Оформление, маршруты, тест, поэтапные задачи, схемы, источники и поиск создаёт общий шаблон. `navigation.js` сохраняет шапку и меню; при переходе заменяется только `main` и активные состояния.

Оркестратор сохраняет базовую копию командой `python tools/migrate_reference.py capture`, запускает **отдельного агента последовательно для каждой темы 3–43, без истории чата**, а после очереди выполняет общую сборку и проверку. Следующий агент начинает только после завершения предыдущего. Чистому окружению нужны зависимости из `requirements-qa.txt`.
